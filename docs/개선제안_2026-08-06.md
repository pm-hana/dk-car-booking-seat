## A. 지금 상태로 전 인원에게 열면 위험한 것 (P0)

### A-1. 저장형 XSS — 예약자 이름이 이스케이프 없이 렌더링됨 ⚠️ 확인된 결함

**현상**: 예약 카드는 사용자 입력을 `unsafe_allow_html=True` HTML에 그대로 끼워 넣는다.

```python
# app.py:2355-2360 — escape 없음
+ _cell(t('c_applicant'), binfo.get('name', ''))
+ _cell(t('c_departure'), binfo.get('departure', ''))
+ _cell(t('c_destination'), binfo.get('destination', ''))
```

반면 관리자 좌석 현황표는 이미 방어되어 있다 — **같은 데이터인데 화면마다 처리가 다르다.**

```python
# app.py:1946-1950 — escape 있음
html.escape(str(src.get("name", "")).strip() or empty),
```

**영향**: 한 사람이 이름·목적지 칸에 `<img src=x onerror=...>` 를 넣으면, 그 예약이 살아 있는 동안 **현황판을 여는 전원의 브라우저에서 실행**된다. 예약 하나로 전 직원 화면이 영향을 받는 구조라 사용자가 늘수록 위험이 커진다. 실수로 `<`, `&` 를 입력해도 레이아웃이 깨진다.

**조치**: 화면 출력 직전 `html.escape()` 일괄 적용(카드 헤더·정보 그리드·좌석 툴팁). 저장값은 그대로 두고 렌더링만 방어.

> 참고: **NGUYỄN VĂN HẢI**(FAE Engineer Staff) — "Daekhon Vina Vision" 2차 개선의 *"có lỗ hổng XSS"* → *"chống XSS"*. 같은 사내 PWA에서 같은 유형의 구멍을 발견해 패치한 사례.

### A-2. 관리자 PIN이 소스에 그대로 (`ADMIN_PIN = "1234"`) ⚠️ 확인된 결함

```python
# app.py:10
ADMIN_PIN = "1234"
```

소스 주석에도 *"이 값은 소스에 그대로 있어 배포 저장소에 노출되는 내부용 간이 게이트"*라고 적혀 있다. 저장소는 `github.com/pm-hana/dk-car-booking-seat`이고, PIN은 **커밋 이력에도 남아 있어 값만 바꿔도 과거 이력에서 조회 가능**하다. 이 PIN 하나로 **전체 예약 초기화**까지 열린다.

**조치**
1. PIN을 `st.secrets["admin"]["pin_hash"]`로 이동 (Streamlit Cloud Secrets — 이미 Firebase 자격증명에 같은 방식을 쓰고 있음, `app.py:619`)
2. 평문이 아니라 해시로 저장, 비교는 `hmac.compare_digest`
3. 4자리 숫자 → 최소 6자리 + 실패 5회 시 잠금(현재 무제한 시도 가능)

> 참고: **Đào Văn Bảo**(FAE Leader) — "K-Pulse" KPI 시스템에서 *"Mật khẩu được lưu không mã hóa"*(평문 저장), *"Khóa cơ sở dữ liệu lộ trong mã trang web"*(키가 페이지에 노출) 문제를 **bcrypt/scrypt 해싱 + 서버측 권한 검사**로 해결.
> 참고: **NGUYỄN TRỌNG CHƯƠNG**(FAE) — `.gitignore`로 `*.key` 및 비밀 설정 파일 커밋 차단.

### A-3. 남의 예약을 아무나 수정·취소할 수 있음

현재 현황판의 **예약 수정 / 예약 취소 / 도착 완료** 버튼은 로그인·본인 확인 없이 전원에게 노출된다. 소수 사용일 땐 문제가 없었지만, 전 인원이 매일 쓰면 **오터치 한 번으로 남의 출근 배차가 사라진다.** 되돌릴 방법도 기록도 없다.

**조치(단계적)**
- 1단계: 취소·수정 시 **본인 이름 확인 1스텝**(신청자 이름 재입력 또는 저장된 내 이름과 일치 시에만 활성) — 관리자는 예외
- 2단계: 취소 시 확인 다이얼로그 + 취소 사유 기록
- 3단계: 판단을 화면(버튼 노출 여부)이 아니라 **저장 직전 서버측에서** 검사

> 참고: **Đào Văn Bảo** — *"Kiểm tra phân quyền được thực hiện trên máy chủ (Server-side), không phụ thuộc vào việc người dùng có ẩn hay vô hiệu hóa nút bấm trên giao diện hay không"* (버튼을 숨기는 것으로는 권한 통제가 안 되고, 서버에서 검사해야 한다). 또한 *"Phân quyền Quản lý giao việc → Nhân viên cập nhật"* 처럼 **관리자 배정 / 직원 갱신**으로 역할을 분리.

### A-4. 전체 예약 초기화에 복구 수단이 없음

관리자 PIN만 통과하면 `🗑️ 전체 예약 초기화`가 가능하고, 되돌릴 방법이 없다. 아침에 실수로 누르면 그날 전 직원 배차가 소실된다.

**조치**
- 관리자 화면에 **원클릭 JSON 백업(Export) / 복원(Import)** 추가
- 초기화 실행 시 **직전 상태 스냅샷을 자동 저장**한 뒤 삭제 → 되돌리기 1회 제공
- 초기화 버튼에 "오늘 N건이 삭제됩니다" 실수 방지 문구

> 참고: **Hà Văn Lượng**(PM Part Leader) — *"Tính năng Export/Import JSON giúp sao lưu toàn bộ thư viện thiết bị; nút Reset 3D khôi phục ngay trạng thái ban đầu chỉ với 1 click"* (원클릭 JSON 백업/복원 + 원클릭 초기화). 파괴적 동작 옆에는 항상 복원 경로를 둔 설계.
> 참고: **Đào Văn Bảo** — *"Thao tác xóa không có hiệu lực"*(삭제가 반영되지 않는 문제)를 **삭제 동기화 + 저장 실패 시 경고 표시**로 해결. 우리도 저장 실패가 현재 조용히 무시된다(`save_bookings`의 `except: pass`, `app.py:695`).

### A-5. 베트남어(Tiếng Việt) 미지원 — 전 인원 사용의 최대 걸림돌

현재 언어는 **한국어 / English 2종뿐**이다(`TR = {"ko": ..., "en": ...}`). 실제 매일 아침 사용할 인원 대다수가 베트남 직원인데, 정작 모국어가 없다.

**조치**: `TR`에 `"vi"` 사전 추가 + 토글 3종(한국어 / Tiếng Việt / English). 사전 구조가 이미 분리돼 있어 **키 추가만으로 끝나며 로직 변경이 없다** — 투입 대비 효과가 가장 큰 항목.

> 참고: 컨테스트 플랫폼(AI Work Booster 2026) 자체가 **한국어 / Tiếng Việt / English** 3종 토글을 기본 제공한다.
> 참고: **Nguyễn Huy Hoàng**(AE Staff) — "Button Design 2.0"의 *"200+ từ khóa song ngữ → icon"* (200개 이상 VI/EN 이중언어 키워드 매핑). 사내 도구는 이중언어가 기본이라는 전제.

### D-3. 이력 무제한 누적 대비
`history`는 계속 쌓이기만 하고, 좌석 현황을 열 때마다 `load_history()`가 **전체를 읽는다**(`app.py:1935`). 전 인원 × 매일이면 1년 뒤 체감 지연이 생긴다.

> 참고: **NGUYỄN VĂN HẢI** — *"dữ liệu & ảnh lưu không giới hạn gây phình DB, dễ văng app"* (무제한 저장으로 DB 비대 → 앱 다운) → 저장 한도·정리 정책 도입.
> 참고: **Lê Khắc Hưng** — *"Khi nạp ảnh có độ phân giải cao mất nhiều thời gian và tiêu tốn nhiều tài nguyên máy"* → 로딩 최적화. 우리는 **날짜 범위 쿼리로 부분 로드** + 오래된 이력 아카이브 분리로 대응.
